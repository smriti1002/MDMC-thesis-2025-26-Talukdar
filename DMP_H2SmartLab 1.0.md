# Data Management Plan

This Data Management Plan (DMP), encoded as DMP_H2SmartLab 1.0 is the first draft for the H2SmartLab project.

---

## 1. Data Description and Collection or Re-use of Existing Data

### a) How will new data be collected or produced and/or how will existing data be re-used?

The new data will be produced from the APSU (for the analysis of hydrogen production, storage and use systems) and MFI (for additional measurements on the hydrogen supply chain) units which is the first node called the H2 Integrated Lab of the workflow-pipeline. The data ingestion process will be managed through the Head PLC operating in read-only mode, ensuring that the data acquisition infrastructure cannot directly interact with or modify the plant automation system for safety and operational reliability reasons. A modular and automated data pipeline will collect the measurements generated by the APSU and MFI instrumentation and transfer them to a Time Series Database (TSDB) hosted within the ORFEO datacentre for storage, monitoring, and further semantic enrichment processes.

The re-use of the existing data could be done by extracting from the data collector, saved in the format of a time-series database which will be enriched with metadata and then further stored in a datacentre ORFEO (database to be decided).

### b) What data (for example the kind, formats, and volumes) will be collected or produced?

The data will be collected in CSV format exported by the central PLC of the APSU and MFI instrumentation. The sampling frequency of the data will be 1 Hz per sensor for 98 sensors and 2 Hz for 5 sensors. The ratio of data writing performance to machine load has to be optimised.

*The methodologies or software that will be used if new data are collected or produced are explained below. The method for data provenance documentation is also explained.*

The operational data pipeline is intended to rely on a Kafka-based streaming architecture designed to manage real-time data events generated by the laboratory instrumentation. The pipeline will follow a modular structure, enabling the separation of data ingestion, data cleaning, metadata enrichment, and storage functionalities. During the enrichment phase, the acquired measurements will be associated with a metadata schema derived from the semantic metadata model defined through the HydLab ontology. The enriched metadata and semantic mappings will be represented through JSON-LD serializations to support interoperability, machine-readability, and semantic integration across heterogeneous systems. The semantically enriched data streams will then be stored within a Time Series Database (TSDB) hosted in the ORFEO datacentre, supporting scalable storage, monitoring, interoperability, and future digital twin integration workflows. The proposed data flow is designed to support future interaction and synchronization mechanisms with the digital twin environment.

The ontological mapping relation with RDF triples can be also pictorially represented (.png).

*The details of the volumes is explained below.*

The volume of the data collected will depend on the number of sensors placed and the frequency with which these sensors are collecting the data.

The data volume in case the collection frequency is 1 Hz for a sensor can be calculated as:

```
Data volume (bytes/s) = Sample size (bytes) × Sampling rate (Hz)
```

The number of sensors along with their sampling rate is as such:

| Sensors | Sampling rate |
|---|---|
| 98 sensors | → 1 Hz |
| 5 sensors | → 2 Hz |

Hence:

```
Data volume (/s) = Sample size (bytes) × {(98 × 1) + (5 × 2)} Hz
                 = Sample size (bytes) × 108 Hz
```

For the 5 sensors collecting data in Boolean:

```
Data volume (/s) = 10 samples/s × 1 byte
                 = 10 bytes/s
```

For the other 98 numeric sensors collecting data in REAL/INT/FLOAT:

**Minimum estimate:**
```
Data volume (/s) = (98 samples/s × 4 bytes) + 10 bytes/s
                 = 402 bytes/s
```

**Maximum estimate (if stored as double):**
```
Data volume (/s) = (98 × 8 bytes) + 10 bytes/s
                 = 794 bytes/s
```

This volume of data is an estimated calculation before the metadata enrichment. This data volume is estimated from the central PLC.

## 2. Documentation and Data Quality

### a) What metadata and documentation (for example the methodology of data collection and way of organising data) will accompany data?

The metadata will be linked to the variables of the parameters measured by the sensors through IRIs. This will enable the data to be queryable. The documentation regarding the methodology of the data collection, organisation of the data and the scripts developed for converting CSV to JSON-LD will be stored in the GitHub repository of the project named as H2SmartLab. The documentation for data schema and ontology mapping will also be presented in the GitHub repository of the project.

### b) What data quality control measures will be used?

Data quality checks will be integrated directly within the operational pipeline through modular validation stages designed to identify inconsistencies, missing values, duplicated timestamps, anomalous measurements, and communication errors during the streaming process. The implementation of these quality-control procedures follows principles inspired by industrial data quality pipelines proposed in recent literature for real-time industrial environments [Peixoto et al., 2025]. The validation and cleaning stages will therefore operate as an integral component of the streaming architecture before metadata enrichment and long-term storage within the ORFEO infrastructure.

## 3. Storage and Backup During the Research Process

### a) How will data and metadata be stored and backed up during the research process?

The raw and semantically enriched data streams will be stored within a Time Series Database (TSDB) hosted in the ORFEO datacentre, which will act as the primary storage infrastructure for both operational and curated data generated by the APSU and MFI units. Temporary buffering and streaming management may be implemented within the ingestion pipeline to support reliable real-time acquisition and processing workflows before long-term storage.

At the current stage of the project, both the physical laboratory infrastructure and the final production-ready database environment are still under development. Consequently, the definitive backup, replication, and disaster recovery strategies have not yet been fully established and will be defined during the commissioning and operational deployment phases of the infrastructure. These strategies will be developed in coordination with the ORFEO infrastructure management team, taking into account scalability requirements, long-term preservation needs, data integrity, and operational reliability of the H2SmartLab ecosystem.

### b) How will data security and protection of sensitive data be taken care of during the research?

The data-security will be maintained with API keys between the data flow in the APSU, MFI and the Hydor Unit of the Hydrogen plant. Personal data management and data security procedures will comply with Regulation (EU) 2016/679 (GDPR), together with applicable institutional and national data protection policies.

---

The legal and ethical requirements, together with the related codes of conduct governing data management and access procedures within the H2SmartLab ecosystem, will be formally defined through the future H2SmartLab data policy, which is currently under development. The policy will regulate aspects related to data ownership, access permissions, intellectual property rights, data sharing conditions, and the management of potentially sensitive operational information.

The codes of conduct adopted within the project will be aligned with the institutional regulations and ethical guidelines applicable to the participating organisations. In particular, research activities and data management practices will follow the principles defined in the codes of conduct for researchers and in the internal code of conduct governing the personnel of Area Science Park, together with any additional institutional and collaborative agreements established among the project partners.

## 4. Data Sharing and Long-term Preservation

### a) How and when will data be shared? Are there possible restrictions to data sharing or embargo reasons?

The conditions for sharing of the data is to be agreed upon the three partners of the project, i.e. AREA Science Park, SISSA and University of Trieste. The project aims to make documentation, metadata, and selected datasets openly accessible whenever possible, while access to operational and raw experimental data may be regulated according to the project data policy and access control procedures. The documentation and the metadata enrichment project will be available to be accessed openly in the GitHub repository of the project. The project follows a FAIR-by-design approach.

### b) How will data for preservation be selected, and where will data be preserved long-term (for example a data repository or archive)?

At the current stage of the project, the long-term preservation strategy and the criteria for selecting data for permanent archival have not yet been fully defined, as both the physical infrastructure and the operational data ecosystem are still under development. The present workflow foresees that raw data generated by the main PLC will be streamed through a Kafka-based pipeline for data validation, cleaning, and semantic metadata enrichment before being stored within a Time Series Database (TSDB) hosted in the ORFEO datacentre.

The long-term preservation policies, including the selection criteria for raw, curated, and semantically enriched datasets, as well as the identification of potential repositories or archival infrastructures, will be established during the commissioning and operational phases of H2SmartLab in coordination with the project partners and the ORFEO infrastructure management team. The preservation strategy will take into account scalability, FAIR compliance, interoperability requirements, long-term scientific reuse, and future digital twin integration needs.

### c) What methods or software tools will be needed to access and use the data?

The data stored within the Time Series Database (TSDB) hosted in the ORFEO datacentre will be accessible through query interfaces compatible with SQL or SQL-like languages, depending on the final database technology adopted within the infrastructure. Access to semantically enriched datasets and metadata may additionally rely on APIs and semantic interoperability services developed within the H2SmartLab ecosystem.

The TSDB environment will implement a Role-Based Access Control (RBAC) system to ensure controlled and differentiated access to the various data layers according to user roles, responsibilities, and authorization levels. The authentication and authorization mechanisms are expected to be integrated with the ORFEO Authentication and Authorization Infrastructure (AAI), enabling centralized identity management and secure access procedures across the infrastructure.

### d) How will the application of a unique and persistent identifier (such as a Digital Object Identifier (DOI)) to each data set be ensured?

During the operational phases of the project, the data streams and records stored within the Time Series Database (TSDB) will be associated with unique internal identifiers to ensure traceability, consistency, and linkage between raw measurements, metadata, and semantically enriched representations across the data pipeline.

For datasets selected for dissemination, publication, or long-term preservation, persistent identifiers such as Digital Object Identifiers (DOIs) will be assigned through suitable trusted repositories or archival platforms adopted by the project partners. The published datasets will be indexed and described through administrative and descriptive metadata including:

- project initiation date and dataset description
- author(s) and contributors
- funding information
- proposal or project identifiers, where applicable
- persistent identifiers associated with publications or dissemination activities
- researcher identifiers (e.g. ORCID)

Datasets made openly available will be distributed under the CC-BY (Creative Commons Attribution) license or other equivalent open-access licenses compatible with the project data policy and applicable institutional regulations.

## 5. Data Management Responsibilities and Resources

### a) Who (for example role, position, and institution) will be responsible for data management (i.e. the data steward)?

The first draft of the Data Management Plan (DMP) has been developed within the framework of the Master in Data Management and Curation (MDMC) by a researcher affiliated with Area Science Park and involved in the H2SmartLab activities. The present DMP primarily addresses the APSU and MFI units managed by Area Science Park and the University of Trieste, while future complementary DMP sections related to the Hydor unit will be developed in collaboration with SISSA.

The DMP and the associated data-management workflows will be progressively reviewed and refined in coordination with the project manager and the responsible personnel of the APSU, MFI, and Hydor units as the infrastructure evolves toward operational deployment.

The operational data management activities will subsequently be supervised by dedicated data stewardship roles responsible for monitoring the organization of the data ecosystem, including documentation, metadata management, version control, semantic interoperability, storage organization, and FAIR compliance procedures. Since the physical infrastructure and the associated digital ecosystem are still under development, the data-management procedures and governance mechanisms will be periodically reviewed and updated during the commissioning and operational phases of the project.

### b) What resources (for example financial and time) will be dedicated to data management and ensuring FAIR compliance?

At the current stage of the project, the first implementation activities related to data management, semantic enrichment, and metadata modelling are being developed within the framework of the MDMC internship activities. These activities include the development of preliminary data pipelines, metadata schemas, ontology mappings, semantic enrichment workflows, and FAIR-oriented documentation procedures.

The operational pipeline is expected to rely on a modular Kafka-based streaming architecture designed for real-time data ingestion, validation, cleaning, metadata enrichment, and storage. Dedicated Python scripts and automated services will process the raw data generated by the PLC systems and transform them into semantically enriched representations based on metadata schemas derived from the HydLab ontology framework.

To support FAIR compliance, the project foresees the adoption of the following measures:

- **Findable** — The datasets and metadata will be associated with unique identifiers and enriched with ontology-based semantic metadata, including IRIs, provenance information, timestamps, sensor identifiers, and standardized units of measurement. Published datasets may additionally receive persistent identifiers such as DOIs through trusted repositories.

- **Accessible** — The data ecosystem will rely on the ORFEO datacentre infrastructure and on controlled access mechanisms based on Role-Based Access Control (RBAC) integrated with the ORFEO Authentication and Authorization Infrastructure (AAI). Access conditions and permissions will be regulated according to the future H2SmartLab data policy.

- **Interoperable** — Interoperability will be supported through the adoption of widely used ontologies and semantic standards, including Schema.org, HOLY, QUDT, UCUM, SOSA/SSN, SensorML, EMMO, BFO, and FOAF. Metadata enrichment will rely on JSON-LD serializations and ontology mappings derived from the HydLab semantic framework, enabling semantic integration across heterogeneous infrastructures and future interoperability with broader federated research ecosystems.

- **Reusable** — The data-management architecture is expected to follow a **Medallion-style layered organisation** within the ORFEO infrastructure:
  - the **Bronze layer** will contain raw acquisition data exported from the instrumentation together with basic provenance metadata
  - the **Silver layer** will contain cleaned, validated, and standardized time-series data enriched with harmonized metadata and semantic identifiers
  - the **Gold layer** will contain semantically enriched and interoperable datasets represented through JSON-LD and RDF-based semantic structures suitable for advanced querying, analytics, and future digital twin integration workflows

The final allocation of long-term financial, infrastructural, and personnel resources dedicated to operational data stewardship, storage, preservation, and FAIR compliance will be defined during the future operational phases of the H2SmartLab infrastructure.
